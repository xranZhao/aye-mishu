# 未尽 · 个人 AI 秘书 PRD

版本：1.0  
产品阶段：单人自用验证期（连续使用 4–6 周）  
目标设备：华为 Pura 70，移动端 PWA  
AI：用户在本机配置 DeepSeek API Key；Key 不写入代码或 GitHub

## 1. 产品目标

未尽不是普通待办清单，也不是要求用户维护精细日历的项目管理工具。它是一个覆盖工作与生活的个人秘书：接住用户随时输入的混乱文字，识别任务、项目、时间意图与依赖，在真实容量内提出直接的排程建议；用户只需确认或纠正，所有计划在确认后才生效。

产品要减少的不是任务数量，而是用户花在“我是不是应该做更多”“这些事到底怎么排”上的焦虑和决策消耗。秘书需要在用户心理上过度 push、现实中经常无法完成时，依据历史实际投入明确指出计划不可信，并给出最小调整方案。

## 2. 核心原则

1. AI 只能建议，用户确认后才写入正式计划。
2. 关键目标优先，必须保留缓冲，允许很多事情不进入本周。
3. 不设观察区。事项只能成为本周承诺、下周事项或以后再说。
4. 本周超容量时，秘书必须明确说明要顺延或取消哪一项；也允许用户选择例外冲刺。
5. 例外冲刺是特殊周，不作为以后提高容量的依据。
6. 周计划提供方向，每天只确认 1–3 件；现实打断后允许当天重排，不视为失败。
7. 明确依赖一经确认，排程严格遵守，前置未完成时后续事项不能进入今日。
8. 每个工作事项必须保留预估时间，并用计时得到实际时间。
9. 生活被秘书完整记录和提醒，但不作为 KPI；关系类事项默认不计时。
10. 秘书的表达直接、基于事实、有鼓励感但不哄骗。

## 3. 用户节奏

- 工作日通常 09:00 起床、23:30 左右休息，最晚 01:00 进入真正休息状态。
- 休息日通常 10:00 起床，最晚 01:00 休息。
- 周六原则上完整休息，不排工作承诺。
- 周日 20:00–23:30 为默认周规划窗口。
- 错过周日不影响使用；周二或任何时间都能补充本周事项，由秘书重新计算剩余容量和依赖。
- 用户主动打开 App；晚间总结提供吸引用户回看的简短反馈，不依赖强制打卡。

## 4. 输入与理解

### 4.1 输入方式

用户使用系统语音转文字输入法，App 只接收文字，不负责录音或语音识别。输入可能混乱、包含多个事项、明确的本周/下周意图、依赖或外部激活信息。

示例：

> 这周需要剪辑 3 个阿野视频，发布 2 条公众号，做好家庭财务规划。公众号要等剪辑完成，客户素材还没给；完成一本书的量下周安排。

### 4.2 AI 需要提取

- 事项名称，保持为可直接开工的粗粒度，不自动拆成细步骤；
- 工作或生活；
- 建议项目归属；
- 用户表达的本周、下周或以后意图；
- 预估时间；
- 依赖事项或外部条件；
- 优先级与排序理由；
- 建议推进日期。

“剪辑视频 A”可以是一个事项；“联系客户”如果只是完成剪辑过程中的动作，不单独建事项。

### 4.3 确认界面

确认界面不是单纯复述抽取结果，而要给出秘书判断：

- 哪些进入本周承诺；
- 哪些进入下周；
- 本周建议顺序和日期；
- 哪些存在依赖、当前是否受阻；
- 本周是否超容量；
- 超容量时应顺延/取消的最小事项，或是否开启例外冲刺。

用户可修改估时、项目归属、依赖与建议日期，然后确认生效。

## 5. 本周计划与动态插入

### 5.1 周计划

周计划以工作块和依赖顺序为主，不要求用户维护小时级日历。秘书将本周承诺排到建议日期；每天打开 App 时，只呈现最值得优先做的 1–3 件。

### 5.2 周中加入事项

无论周几，用户都可直接输入新事项。秘书立即结合以下信息重新判断：

- 本周剩余可靠容量；
- 已确认的本周承诺；
- 已经产生的实际投入；
- 剩余工作日与周六休息规则；
- 任务依赖和外部阻塞；
- 新事项的优先级与不完成代价。

若全部加入不可信，秘书直接否决“全部本周完成”，并给出最小调整方案。用户可选择：

1. 顺延秘书指出的旧事项，再插入新事项；
2. 将新事项放到下周；
3. 明确开启例外冲刺。

不存在观察区。

### 5.3 外部条件激活

当用户输入“客户给素材了”“小李回复了”，秘书识别为依赖解除，找出因此被激活的受阻事项，重新提出今日或本周排程。若插入今日会挤掉原计划，必须说明替换哪一件并等待确认。

## 6. 依赖排程

- 支持事项依赖事项，例如 A → B → C；
- 支持事项依赖外部条件，例如“收到客户素材”；
- AI 提出依赖建议，用户确认；
- 前置条件未满足时，事项显示受阻原因，不进入今日清单；
- 前置完成或外部条件激活后，后续事项自动变为可安排，但不会未经确认挤入今日；
- 建议日期必须服从依赖，不允许 B 早于 A。

## 7. 计时与估时校准

### 7.1 工作计时

- 工作事项可开始计时；
- 暂停只停表，保持在专注界面；
- 暂停后可继续，显示该事项累计实际投入，不从零开始；
- 关闭专注界面不丢失暂停状态；
- 点击结束后询问“已完成 / 还没完成”；
- 未完成时要求重新填写预计剩余时间；
- 已完成时记录最终实际投入与初始预估的差异。

### 7.2 时间显示

- 未开始：预计 X；
- 进行或暂停：已投入 X，预计剩余约 Y；
- 已完成：实际 X，较预估多/少 Y；
- 实际投入按秒保存，展示可按秒/分钟/小时自适应。

### 7.3 生活计时

- 家务或财务管理可选计时；
- 与亲友通话、吃饭、聊天等关系事项默认不计时；
- 不计时不代表不占现实时间，秘书排程时仍需考虑它们；
- 生活事项不进入工作完成率和专注容量 KPI。

## 8. 今日首页

- 工作区显示当天确认的 1–3 件；
- 依赖未满足的事项不出现为可执行项；
- 第一项突出显示并可直接计时；
- 生活区提醒当日或本周值得留出空间的安排；
- 输入成功后清空输入框；
- 操作提示不遮挡输入框和底部导航；
- 晚间摘要文案：今天投入 X；本周关键事项还差 Y；明天最值得先做的是 Z。

## 9. 周报

周报按自然周生成并保存快照，包含：

1. 工作承诺：完成、未完成、受阻、预估和实际；
2. 生活安排：完成或未完成，但不计算工作完成率、不占工作专注容量；
3. 总实际专注投入；
4. 每项和整体估时偏差；
5. 容量判断：本周计划是否可信、例外冲刺是否发生；
6. AI 判断：基于真实数据解释发生了什么；
7. 下周建议：延续、取消、调低/提高容量、先解决哪些依赖。

有 DeepSeek Key 时生成真正的 AI 判断。没有 Key 或请求失败时，只显示明确标注的“本地规则摘要”，不得把固定模板伪装成 AI。

周报支持保存历史记录，并导出 Markdown；完整数据支持 JSON 备份，任务支持 CSV 导出。

## 10. 数据与学习

- 所有数据默认保存在当前设备 localStorage；
- API Key 只保存在本机，不写入代码、仓库或导出的公开内容；
- AI 每次排程可读取本机整理后的必要上下文；
- 4–6 周后，以实际数据学习用户的可靠容量、估时偏差、精力曲线和常见受阻原因；
- 例外冲刺数据单独标记，不作为常态容量训练样本；
- 换手机前可导出完整 JSON，后续应支持恢复导入。

## 11. 状态模型

工作事项状态：

- 本周承诺；
- 下周；
- 受阻；
- 进行中；
- 暂停；
- 完成。

明确取消“本周候选”和“观察区”。

生活事项状态：

- 本周安排；
- 下周；
- 完成。

## 12. 验收标准

1. 周二输入多项本周工作，App 能回复并给出容量与日期建议。
2. 超容量时不能直接全部录入本周，必须先给顺延项或例外冲刺选项。
3. A 依赖 B 时，B 未完成前 A 不进入今日。
4. 暂停计时后仍停留在专注页，继续后累计时间不归零。
5. 确认录入后输入框清空，任务卡之间无逗号。
6. 周报同时显示工作与生活，生活不进入工作完成率和工作容量。
7. AI 判断引用本周真实数据；无 AI 时明确标注本地摘要。
8. 周报保存后不随下一周数据变化。
9. 设置页不再显示安装应用卡片。
10. 不把 Android 系统手势黑条作为本轮修复范围。
