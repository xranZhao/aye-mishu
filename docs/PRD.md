# 未尽 · 个人 AI 秘书 PRD

版本：3.0

阶段：单人自用验证期（先连续使用 4–6 周）

设备：华为 Pura 70，移动端 PWA

AI：DeepSeek V4 Pro；API Key 仅保存在当前浏览器

## 1. 产品目标

未尽不是普通待办清单，也不是要求用户维护小时级日历的项目管理工具。它是一个覆盖主业、个人项目与生活安排的个人秘书：接住用户随时输入的混乱原话，通过连续对话理解真实事项、项目、依赖和时间意图，在可靠容量内提出周一至周日的安排；所有变更由用户确认后才生效。

产品要减少的是用户在“到底先做什么”“这些事情能不能同时完成”“现实变化后如何重排”上的焦虑和决策消耗。用户容易在心理上过度 push 自己，但现实中经常无法完成，因此秘书必须依据真实计时和历史完成情况指出不可信计划，并给出最小调整方案。

## 2. 秘书人格

- 冷静、明确，直接程度保持中间态。
- 先给一个推荐结论，再说明事实依据与被影响的事项。
- 可以说“不行，按当前容量这些事本周放不下”，但不评价用户的人格或自律程度。
- 鼓励只引用事实，例如“今天实际投入了 83 分钟”，不使用空洞表扬。
- 通常给一个最推荐方案；只有存在真实权衡时才给替代方案。
- AI 只能建议，用户确认后才改变正式计划。

## 3. 用户节奏与初始容量

- 工作日通常 09:00 起床，23:30 左右休息，最晚 01:00 进入真正休息。
- 休息日通常 10:00 起床，最晚 01:00 休息。
- 周六保持完整休息，不排工作承诺；生活安排可以出现。
- 周日 20:00–23:30 是默认周规划窗口，但错过周日仍可在任何一天补做规划。
- 初始个人项目可靠容量为每周 7 小时：工作日晚合计约 4 小时、周日约 3 小时；额外时间不自动成为可承诺容量。
- 初始主业显式专注任务容量为每周 20 小时，和个人项目容量分开。
- 连续使用四周后，以真实计时、完成情况和精力曲线校准容量。
- 例外冲刺单独标记，不能用于提高未来常态容量。

## 4. 项目组合

### 4.1 项目与当月配置

| 项目 | 项目组 | 当前月状态 | 规则 |
|---|---|---|---|
| 主业 | - | 固定基本盘 | 使用主业容量，保护稳定现金流和保障 |
| 阿野在武汉 | 阿野IP | 本月最高重点 | 保护获客入口和主业变化的时效内容 |
| 是阿野吖 | 阿野IP | 本月次重点 | 独立创作，有合适深度选题时安排 |
| 磕学家 | - | 最低必要维护 | 已有每月约 100–200 元收入；每月最多 8 小时，不要求做满 |
| 家庭财务 | - | 最低必要维护 | 只处理本月真正重要的事项 |
| 基金理财 | - | 低频推进 | 不因“应该学习”自动占满时间 |
| 任推帮 | - | 机会型投入 | 有明确收益机会时再投入 |
| 神图 | - | 暂停保存 | 不分配常规容量 |
| PPT接单 | - | 暂停保存 | 不分配常规容量 |

### 4.2 项目规则

- 项目数量没有硬上限，但新项目不会自动获得本周容量。
- 只有“独立长期结果 + 持续工作量”同时成立时才建立新项目；短期活动或一批内容归入现有项目。
- 阿野在武汉与是阿野吖是两个独立创作项目；内容可以复用，但默认不存在硬依赖。
- 两个阿野项目冲突时优先保护阿野在武汉。
- 项目状态按月生效，不能固化为永久优先级。
- 每月最后一个周日，秘书展示实际投入、结果、收入和状态，重新询问用户下月重点。
- 月中发生主业变化、收入风险或重要机会时，可以提前触发项目组合复盘。

## 5. 核心信息架构

底部导航：今天｜本周｜秘书｜复盘｜设置。

“秘书”是统一的任务沟通入口，同时处理：

1. 周日大型梳理；
2. 周中加入新事项；
3. 客户给素材、他人回复、临时加班等现实变化；
4. 逾期事项集中处理；
5. 月度项目复盘。

首页和其他页面的全局输入框是快捷入口。提交后进入秘书会话，不直接写入任务。

## 6. 秘书会话

### 6.1 状态边界

1. 原始表达：保留用户完整原话。
2. 对话草稿：AI 对原话的临时理解，可继续补充和纠正，不占容量。
3. 排程建议：完成项目、估时、依赖、日期与容量检查，等待确认。
4. 正式计划：用户确认后才写入本周、下周或受阻事项。

对话草稿不是观察区。它不作为长期任务状态，不会伪装成可完成承诺。

### 6.2 周日大型梳理

流程：

> 理解原话 → 总结真实事项 → 识别项目 → 补问关键歧义 → 确认依赖和估时 → 检查容量 → 生成周一至周日方案 → 用户最终确认

- 用户可以分多次输入；AI 每轮更新理解，但不急于录入。
- 用户点击“我说完了，开始整理”后，AI 才统一生成排程。
- AI 不把“这是测试”“我梳理一下”等话语组织成分识别为任务。
- AI 不把一个粗粒度事项拆成执行步骤。
- 建议项允许删除、新增、改名、改项目、改估时、改日期、改依赖。

### 6.3 周中新增

- 用户任何时间都可直接输入新事项。
- AI 读取当前承诺、已投入时间、剩余容量、剩余日期、项目重点和依赖。
- 若可以加入，明确建议日期及理由。
- 若会挤掉旧事项，必须明确说“要插入它，建议顺延/取消哪一件”。
- 若全部完成不可信，必须直接否决，并给最小调整方案。
- 用户可以将新事项放到下周，或明确开启例外冲刺。
- 不存在观察区。

### 6.4 现实变化

当用户输入“客户给素材了”“小李回复了”时，AI 判断它是否解除某个外部条件，并找到因此可激活的事项。激活后若进入今天或本周会挤掉原安排，仍要给替换建议并等待确认。

## 7. 事项与依赖

### 7.1 事项颗粒度

- 事项应保持用户可直接开工的粗粒度，例如“剪辑阿野视频 A”。
- “联系客户”若只是完成剪辑过程中的动作，不单独建事项。
- “和姐姐通话”“和老公吃饭”属于生活安排，不作为工作 KPI。

### 7.2 估时

- 每个正式事项都必须由用户确认预计时间。
- AI 可根据历史同类事项给参考，并指出明显不可信的估时。
- 计时结束后记录预计时间、实际投入和剩余估时。
- 没有确认估时的内容只能留在当前对话草稿，不能进入正式周计划。

### 7.3 依赖类型

- 硬依赖：前置未完成，后续绝不能开始。
- 外部条件：等待素材、他人回复、场所开放等。
- 建议顺序：先做 A 更合理，但不是强制阻塞。

AI 提出判断，用户确认后生效。硬依赖必须保证后续日期不早于前置事项；安排在同一天时，前置未完成前后续事项不能进入今日可执行列表。外部条件未满足时事项显示受阻，不能进入今天。

## 8. 周历与今日确认

- “本周”显示周一至周日，而不是单一任务列表。
- 普通事项只排到某一天，不维护小时级日历。
- 只有有明确时间点的生活或办事事项显示具体时间。
- 每天打开 App，只显示当天确认的 1–3 件优先事项。
- 周六显示休息，不排工作承诺。
- 生活安排显示在日期下，但不扣工作专注容量。

## 9. 逾期处理

- 计划日期已过且未完成的事项进入“逾期待决”，不得自动滚入第二天。
- 第二天打开 App 时，集中提示逾期数量。
- 用户进入秘书后，AI 给一份集中处理方案：移动日期、放到下周、取消或标记受阻，并解释理由。
- 用户可以“一键按秘书建议处理”“逐项调整”或暂不处理。
- 暂不处理的事项保持逾期待决，不进入今天。

## 10. 计时与校准

- 工作事项支持开始、暂停、继续和结束。
- 暂停只停表，仍停留在专注页面；继续时累计真实投入，不从零开始。
- 结束后询问“已完成 / 还没完成”。
- 未完成时必须填写预计剩余时间，不自动滚到明天。
- 关系类生活安排默认不启用计时器；它们仍作为现实时间约束参与排程。
- 生活不进入工作完成率、专注容量或效率 KPI。

## 11. 复盘

### 11.1 每日小结

默认 22:30 后打开 App 显示：

> 今天投入了 X；本周关键事项还差 Y；明天最值得先做的是 Z。

PWA 无后台推送能力时，不能伪装成已发送通知；下次打开时补展示。

### 11.2 周报

- 工作承诺：完成、未完成、受阻、预计与实际。
- 生活安排：单独展示，不计工作完成率。
- 总专注投入与估时偏差。
- 项目投入、容量可信度和例外冲刺。
- AI 必须引用本周真实数据解释发生了什么。
- 下周建议必须明确继续、顺延、取消、调估时或先解除哪个依赖。
- 周报保存为快照，并支持 Markdown 导出；完整数据支持 JSON，任务支持 CSV。

### 11.3 月度复盘

- 按项目展示实际投入、结果、收入和当前状态。
- AI 询问用户当前最担心与最想保护的方向。
- AI 提出下月项目组合建议，用户确认后生效。
- 月度状态月底到期，下月必须重新确认。

## 12. AI 调用与失败

所有关键判断真实调用 DeepSeek V4 Pro：

1. 原话理解；
2. 项目识别；
3. 依赖与关键问题判断；
4. 周排程；
5. 周中重排与逾期处理；
6. 周报与月度项目复盘。

AI 失败时必须：

- 保留用户完整原话和当前对话草稿；
- 显示缺少 Key、鉴权、余额、限流、网络、超时或结构错误；
- 提供重试；
- 禁止回退到标点拆分；
- 禁止把本地模板冒充 AI 判断。

## 13. 数据与隐私

- 所有数据默认保存在当前浏览器 localStorage。
- API Key 不进入 Git、公开导出或周报 Markdown。
- AI 每次只读取完成当前判断所需的项目、计划、历史估时和近期对话。
- 完整 JSON 备份默认移除 API Key。
- 先服务单个用户并积累 4–6 周真实数据，不提前扩展团队权限与协作。

## 14. 核心验收场景

1. 用户说一段包含铺垫和多个事项的混乱原话，App 不产生“这是测试”等伪任务。
2. 没有 DeepSeek Key 或请求失败时，原话仍保留并显示可见错误，不进行标点拆分。
3. 周日可连续输入多轮，点击“我说完了”后才生成可编辑周计划。
4. 周二加入新事项时，AI 对比已有承诺并明确建议替换或顺延哪一项。
5. A 硬依赖 B 时，B 未完成前 A 不进入今天且日期不得早于 B。
6. 外部条件解除后，AI 找到被激活事项并提出新的排程建议。
7. 逾期事项第二天不自动进入今天，而是由秘书给集中处理方案。
8. 本周页按周一至周日显示确认事项，周六不排工作。
9. 主业与个人项目使用不同容量池，个人项目不得自动占用主业时间。
10. 暂停计时后留在专注页，继续后累计时间不归零。
11. 周报必须引用真实任务和计时数据；月报显示项目投入与收入。
12. 所有 AI 建议都可编辑，用户确认后才写入正式计划。
